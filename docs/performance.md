# Performance and native feel

What is already configured, where it lives, and the rules that keep it fast. Measure on a release build before and after any change.

## Defaults from the SDK

SDK 57 / React Native 0.86 give these with no configuration: New Architecture, Hermes V1 with precompiled bytecode, an uncompressed memory-mapped bundle on Android, precompiled React Native on iOS, edge-to-edge on Android and 120 Hz on ProMotion iPhones.

Do not set `enableBundleCompression` or `useLegacyPackaging`, and never edit `ios/` or `android/` by hand: they are regenerated by prebuild. Native settings go through `app.config.ts` and config plugins.

## React Compiler

On through `experiments.reactCompiler` in `app.config.ts` (`babel-preset-expo` already bundles the plugin; do not add it to Babel).

- Write plain components: no `useMemo`, `useCallback` or `React.memo` for performance. Keep them only when an effect must not re-run unless a value really changed.
- The compiler silently skips code that breaks the Rules of React. ESLint reports it, and `react-hooks/rule-suppression` makes any `eslint-disable` of a hooks rule an error.
- Values shared by every instance go in module scope (`useStyles` cache, `Intl` formatters), not in hooks.
- Zustand selectors that return a new object or array need `useShallow`.
- `'use no memo'` opts a file or component out; use it only to bisect a compiler bug.

Check it works: Metro prints `React Compiler enabled`, and React Native DevTools (`j` in Metro) shows a **Memo ✨** badge on compiled components.

## Startup

1. Native splash with the theme colours (light and dark), root view coloured by expo-system-ui.
2. Hermes maps the bytecode bundle. Release builds use inline requires, so modules load on first use.
3. Expo Router evaluates every `_layout.tsx` module. The root layout calls `bootstrap()`.
4. Providers mount; the persisted query cache is restored from MMKV.
5. The root navigator reads the session (already in memory: the session store read SecureStore and MMKV synchronously at import), renders home or sign-in, and Expo Router hides the splash. That first screen calls `markScreenInteractive('home' | 'sign-in')`.
6. Deferred SDKs run in `requestIdleCallback` (at most 3 s later).

Rules for the startup path:

- Keep `_layout.tsx` files thin; their imports run before the first frame.
- Only crash reporting goes in `criticalInitializers`; everything else in `deferredInitializers`. See `src/config/sdks/README.md`.
- No async storage on the startup path. MMKV and SecureStore are synchronous, so the language and auth token exist on the first render.
- Use the system fonts, or embed brand fonts with the `expo-font` config plugin instead of `useFonts`.
- `preview` and `production` builds set `EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH=1` and `EXPO_UNSTABLE_TREE_SHAKING=1` in `eas.json`. If you adopt `eas update`, pass the same flags, or the update will not match the tested build.
- `babel.config.js` strips `console.log`, `.info` and `.debug` from release bundles.

## Navigation and native feel

- Navigation theme built from our tokens (`shared/theme/navigation-theme.ts`): no white header or white flash in dark mode.
- The app and section stacks set `freezeOnBlur: true`, so hidden screens stop re-rendering.
- Tabs are `NativeTabs` (`expo-router/unstable-native-tabs`): the platform tab bar, Liquid Glass and minimize-on-scroll on iOS 26, Material on Android. Every tab mounts at start, so a tab with heavy work defers it with `useIsFocused` / `useFocusEffect`.
- Each tab and drawer item is its own native Stack with an iOS large title. The first native child must be the scroll view (`<ScrollScreen>` or `<List>`), so the title collapses, content clears the tab bar and the bar minimizes.
- The drawer uses `drawerType: 'front'` (the native tab bar does not slide) and swipes open on Android only; on iOS the edge swipe stays the back gesture.
- Icons are SF Symbols on iOS and Material Symbols on Android (`<Icon>`, expo-symbols). On Android expo-symbols draws them with the Material Symbols font, loaded on first use, so an icon can appear a frame after its screen. Icons are decorative: the surrounding control carries the accessibility label.
- Sign-out confirmation is a native `Alert` with a destructive action.
- `Button` and `ClubCard` use the native Android ripple and a `pressed` style on iOS, without re-rendering on press.
- Sheets use `presentation: 'formSheet'` with `sheetAllowedDetents` (see `/sheet` in `AppStackLayout`).
- Predictive back is off until react-native-screens supports its animations.

## Data, lists and images

- **Storage.** `shared/lib/storage/storage.ts` routes normal keys to MMKV and keys in `SECRET_KEYS` to expo-secure-store. Never put secrets in `persistStorage`.
- **Persisted cache.** Only successful queries with `meta: { persist: true }` are written to MMKV (throttled, dropped after 24 h or on a new app version). Clubs are persisted, members (personal data) are not.
- **Focus and online.** Stale data refetches when the app returns to the foreground; queries pause while offline.
- **Instant detail screens.** The detail query starts from the cached list item (`placeholderData`), and the members request starts on touch down (`onPressIn`).
- **Refresh.** Only a pull shows the spinner; never use `refreshing={query.isRefetching}`.
- **Lists.** Always `<List>` (Legend List, recycling on) with a stable `keyExtractor` and a realistic `estimatedItemSize`. Never nest a vertical list inside a `ScrollView`.
- **Images.** Always `<Image>` (expo-image, memory + disk cache). In recycled rows pass `recyclingKey={item.id}` and a `placeholder`.

## Animations

Reanimated 4 and Gesture Handler are installed and the app is wrapped in `GestureHandlerRootView`. Prefer Reanimated's CSS transitions for state changes, worklets for gestures and scroll, animate `transform` and `opacity`, and use `.get()` / `.set()` on shared values.

## Android release size

`expo-build-properties` turns on R8 and resource shrinking for release builds. If a release build crashes with a missing class, add a keep rule through `extraProguardRules`, and test on a `preview` APK.

## Native dependencies

`react-native-nitro-modules` is pinned to exactly `0.37.1`: its native ABI must match every Nitro library, so upgrade it only together with them. Any library with native code needs `bunx expo install` and a new development build.

Worth adding only when a measurement says so: [react-native-nitro-fetch](https://github.com/margelo/react-native-nitro-fetch), [Unistyles v3](https://unistyl.es), [react-native-keyboard-controller](https://kirillzyusko.github.io/react-native-keyboard-controller/), [react-native-release-profiler](https://github.com/margelo/react-native-release-profiler), [expo-observe](https://docs.expo.dev/versions/v57.0.0/sdk/observe/).

## Measuring

Use a release build (`preview`) on a mid-range device; development builds are not representative.

| Tool | Use |
| --- | --- |
| React Native DevTools (`j` in Metro) | Timeline with our marks (`bootstrap:*`, `tti`), React profiler |
| `adb shell am start -W -n com.jvegax.nativetemplate.preview/.MainActivity` | Android cold start time |
| Xcode Instruments, App Launch | iOS launch phases |
| [Flashlight](https://github.com/bamlab/flashlight) | Android FPS, CPU and RAM |
| [Expo Atlas](https://docs.expo.dev/guides/analyzing-bundles/) | Bundle contents. Run on demand only and do not commit it (its `stream-json` dependency has an open advisory) |
